### 3. Step-by-Step Request Flows

#### (a) Login Flow
1. User enters email, password, and optional rememberMe flag on the frontend form (`frontend/src/pages/Login.jsx`).
2. Frontend sends `POST http://localhost:5000/api/auth/login` (`frontend/src/services/api.js:82`).
3. Express router passes request through `authRateLimiter` (`backend/routes/authRoutes.js:42`).
4. Controller `loginUser` executes (`backend/controllers/authController.js:145`):
   - Queries `User.findOne({ email }).select('+password')`.
   - Checks `user.lockUntil`. If locked and time remaining, returns HTTP 423 `ACCOUNT_LOCKED`.
   - Compares password using `user.matchPassword(password)` (`bcrypt.compare`).
   - If mismatch: increments `user.failedLoginAttempts`. If attempts $\ge 5$, sets `user.lockUntil = Date.now() + 15 * 60 * 1000`. Returns HTTP 401.
   - If match: resets `failedLoginAttempts = 0`, generates access token (15m expiry) via `generateAccessToken(user._id)`.
   - Generates random 40-byte refresh token, hashes it via `sha256()`, stores hash in `user.refreshTokenHash`, and sets HttpOnly cookie (`refreshToken`) on response.
5. Frontend receives `{ success: true, accessToken, user }`, saves accessToken in memory and localStorage fallback, and redirects to `/dashboard`.

#### (b) Starting an Interview Flow
1. User selects stream (technical/hr), subject (java/dbms), difficulty (easy/medium/hard), format (theory/output_prediction/coding), and count on `frontend/src/pages/InterviewSetup.jsx`.
2. Frontend invokes `createInterview(config)` sending `POST http://localhost:5000/api/interviews` (`frontend/src/services/api.js:156`).
3. Express router guards route via `protect` middleware (`backend/routes/interviewRoutes.js:16`), extracting authenticated `req.user`.
4. Controller `createInterview` (`backend/controllers/interviewController.js:14`) calls `generateNextQuestion()` (`backend/services/interviewEngine.js:29`).
5. `interviewEngine.js` sends `POST http://localhost:8000/api/ai/generate-question` to FastAPI AI microservice (`backend/services/aiService.js:8`).
6. FastAPI routes request to `generate_question` endpoint (`ai-service/app/routes/question_routes.py:22`), invoking `LlamaModel.generate_question()` (`ai-service/app/models/llama_provider.py:2100`).
7. AI service generates question statement, expected concepts, and initial starter code / test cases, returning `QuestionResponse`.
8. Backend creates new `Interview` record in MongoDB with `status: 'in-progress'` and stores the question payload in `currentQuestionData` (`backend/models/Interview.js:38`).
9. Response `{ success: true, interview, question }` returned to frontend; browser transitions to `/interview/:id`.

#### (c) HR Answer Submission and Evaluation Flow
1. Candidate types or dictates answer and clicks "Submit" (`frontend/src/pages/Interview.jsx`).
2. Frontend sends `POST http://localhost:5000/api/interviews/:id/answers` (`frontend/src/services/api.js:168`).
3. Controller `submitAnswer` (`backend/controllers/interviewController.js:125`) retrieves active interview and forwards payload to AI service `POST http://localhost:8000/api/ai/evaluate-answer`.
4. FastAPI routes to `evaluate_answer` (`ai-service/app/routes/evaluation_routes.py:8`), calling `_evaluate_hr_answer()` (`ai-service/app/models/llama_provider.py:3080`).
5. **Deterministic Off-Topic Gate**: Calls `is_off_topic(question, answer)` (`ai-service/app/utils/hr_gate.py:86`).
   - If answer matches 0 question topic keywords, immediately returns `score: 0`, `isIrrelevant: True`, bypassing model inference.
6. If on-topic: computes BERT semantic similarity (`embedding_service.py`), formats prompt with STAR rubric guidelines, and invokes fine-tuned LLaMA model (`model_override=self.ft_model_name`) at temperature 0.0 (`llama_provider.py:3140`).
7. Extracts metrics (`correctness`, `relevance`, `accuracy`, `communication`) and computes final overall score via `calculate_hr_overall()` (`ai-service/app/utils/hr_scoring.py:24`).
8. AI service returns `EvaluationResponse`. Backend creates `Answer` document in MongoDB (`backend/models/Answer.js`).
9. Increments `interview.attemptedCount`. If `attemptedCount >= questionsCount`, marks `interview.status = 'completed'` and generates aggregate `Result` record.
10. Evaluation details and next question returned to frontend.

#### (d) Java Coding Submission Flow
1. Candidate writes Java method in the CodeWorkspace editor and clicks "Run Tests" or "Submit Solution".
2. Request `POST /api/interviews/:id/answers` arrives at `interviewController.js:125`.
3. Backend forwards `language: 'java'`, candidate code, and test cases array to AI service `POST /api/ai/evaluate-answer`.
4. `llama_provider.py:3316` calls `execute_coding_submission()` in `ai-service/app/services/code_executor.py:292`.
5. Code executor creates temporary isolated directory (`tempfile.mkdtemp()`).
6. Generates `Solution.java` containing candidate code and compiles it via `javac -encoding UTF-8 Solution.java`.
   - If compile fails: captures error string, sets `score = 0`, `compileError = stderr`.
7. If compile succeeds: writes reflection runner `MockMateRunner.java` and executes each test case via `java -cp . MockMateRunner Solution <input>` under `timeout = 5.0s`.
8. Compares stdout against `expectedOutput`, computing `passedCount` and `totalCount`.
9. Concurrently, calls `_analyze_code_complexity()` (`llama_provider.py:3273`) invoking the fine-tuned model to deduce asymptotic Time and Space Big-O notation.
10. Persists `Answer` document in MongoDB with `testCaseResults`, `timeComplexity`, `spaceComplexity`, and `score`.

#### (e) SQL Coding Submission Flow
1. Candidate writes SQL query and submits.
2. Request reaches AI service `_evaluate_coding_answer()` with `language: 'sql'`.
3. Calls `execute_sql_submission()` in `ai-service/app/services/code_executor.py:530`.
4. Establishes in-memory SQLite database connection (`sqlite3.connect(":memory:")`).
5. Executes DDL schema (`CREATE TABLE ...`) and inserts sample DML data.
6. Executes reference solution query to extract expected row tuples and column headers.
7. Executes candidate query to extract actual row tuples and column headers.
8. Asserts row and column equivalence: if rows match exactly, `score = 100`, else `score = 0`.
9. Closes SQLite in-memory connection and returns test result structure.

#### (f) Code Complexity Analysis Flow
1. Invoked automatically during coding evaluations or standalone analysis.
2. Method `_analyze_code_complexity(question, code, lang)` executes (`ai-service/app/models/llama_provider.py:3273`).
3. Formats prompt `build_training_style_prompt("analyze_code_complexity", input_dict)` (`prompt_templates.py:88`).
4. Selects model: `settings.FINE_TUNED_MODEL_NAME` (`mockmate-hr100` / `mockmate-llama-ft`).
5. Invokes Ollama API at `temperature = 0.0`, `num_predict = 256`, `response_format = "json"`, `timeout = 45`.
6. Extracts `timeComplexity` (e.g. `O(N)`), `spaceComplexity` (e.g. `O(1)`), and `explanation`.
7. If call fails or output lacks Big-O notation, invokes `_estimate_code_complexity_heuristic(code)` regex fallback.

  def calculate_hr_overall(correctness, relevance, accuracy, communication) -> int:

      Average of the four factors as shown to the candidate, so the overall score

## S16 Limitations

1. **Unit Test Regressions:**
   - Five unit tests in `ai-service/tests/` fail during automated execution:
     - `test_generic_hr_keywords_are_not_related_and_skip_the_llm` and `test_unrelated_answer_is_not_related_to_the_question` fail because the expected error string was hardcoded to `"Not related to the question."`, whereas the active code returns `"The answer is not about this question; score 0."` and `"The response does not address the question asked, so no credit can be given."`.
     - `test_configured_model_is_used_strictly` asserts model name is `"mockmate-llama-ft"`, whereas active `.env` configuration sets `"mockmate-hr100"`.
     - Two model audit tests fail because the Ollama instance is running a base model alias rather than a verified standalone GGUF file.
2. **Fallback Secrets in Code:**
   - `backend/middleware/authMiddleware.js:16` and `authController.js:28` contain a fallback hardcoded secret string: `'ai_interview_assistant_jwt_secret_key_2026_super_secure'` when `JWT_SECRET` is omitted from environment variables.
3. **No Role-Based Access Control:**
   - There is no `role` field on the `User` schema (`backend/models/User.js`). All authenticated users have identical privileges.
4. **Editor Simplicity:**
   - The coding interface uses an HTML `<textarea>` with synchronized CSS line numbers and custom tab key event listeners rather than Monaco Editor or CodeMirror.
5. **Heuristic Complexity Derivation on LLM Failure:**
   - If the fine-tuned model times out or returns non-JSON output, code complexity falls back to regular expressions rather than building a true compiler abstract syntax tree (AST).
6. **Local Ollama Model Digest Parity:**
   - The registered Ollama model `mockmate-llama-ft` has digest `174faa587450` (2.0 GB), which shares the exact same base blob as `llama3.2:3b`. True fine-tuned weights are present in `mockmate-hr100:latest` (3.4 GB) and `mockmate:latest` (3.4 GB).
